# Rules log — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A toggleable text log that explains every damage calculation and every effect outcome, with server-assigned creature tags drawn while the log is on. It never lies, never changes the simulation, costs nothing while off, and never reveals what the player cannot see.

**Architecture:** The server records each step **while it computes it**. A hit carries its provenance (`Damage.why`: who, with what, the Attribute breakdown, the multipliers) from where it is built to the hurt function. The hurt function and the single effect apply path then write one record: a headline plus its detail lines, as text, with the creatures it names. Recording happens only while some player has the log on (`Run::log_on()`). At snapshot time each record goes to a player only if that player sees every creature in it. The one exception is a short line for damage the viewed hero (or its wolf) takes from something unseen. The client shows the lines in a DOM panel and draws the tags.

**Tech Stack:** Rust (server, `cargo test`), TypeScript + Phaser (client, vitest), ts-rs bindings (`client/src/generated`), msgpack (`server/src/wire.rs`, `client/src/wire.ts`).

**Spec:** [docs/superpowers/specs/2026-10-21-rules-log-design.md](../specs/2026-10-21-rules-log-design.md). Read it whole; "Who sees which lines" is binding.

## Global Constraints

- **The log never lies:** every logged number is the value the rule used: the same variable, or a breakdown that the rule's value is itself computed from (`Base::amount()` *is* the ability's damage). No function may recompute a number for the log alone.
- **The log never changes the game:** `level_setup_is_unchanged`, `simulation_is_unchanged_after_waking_the_boss` and `plan_3a_fight_is_pinned` (`server/src/run/mod.rs`) pass unchanged after every task, with the log off **and** (from Task 2 on) with every player's log on. Nothing is re-recorded. No new RNG draw, and no change to the order of float operations in any rule.
- **Off costs nothing:** with no player's log on, no record is built, no string is formatted, and the encoded snapshot is byte-for-byte what it is today (the new trailing field is skipped).
- **Names** (the user): "Attributes", never "ability scores"; "ability" means only the LMB primary and RMB secondary; never "elemental", say "damage-type effect". No chance anywhere.
- **No wildcard arms** over `AbilityId`, `Shape`, `EffectKind`, `EffectLook`, `AbilityMod`, `PropKind`, `WeaponKind`, `EquipSlot`, `DamageType`, `EntityKind`, or the new log enums (`What`, `Mult`, `EffectOutcome`, `Skip`, `LineKind`). Each new log enum's text is an exhaustive `match`, so a variant without text does not compile.
- **Rounding:** one decimal everywhere, with a trailing `.0` dropped (`n1(9.0) == "9"`, `n1(10.55) == "10.6"`, `n1(-0.04) == "0"`). Percentages are whole numbers (`pct(0.2) == "20 %"`).
- **Text from the server:** records go out as pre-formatted lines (headline + detail lines + a `LineKind` for the colour). The client only shows, filters and colours them. (The spec left the wire shape open; text keeps the formatting, its exhaustive matches and its tests in one place, next to the numbers.)
- **Sandbox:** `cd server && cargo test -- --skip export_bindings` (focused: `cargo test --bin '*' <filter> -- --skip export_bindings`). **A task that changes exported data** (protocol, wire, `defs.ts`) regenerates `client/src/generated` with `docker compose -f docker-compose.test.yml run --rm test` from the repo root and commits the changes. If docker is unreachable from the sandbox, the task report says so and the main session runs it.
- **Client checks:** `cd client && bash -lic 'npx vitest run && npx tsc --noEmit && npm run build'`.
- **Commits:** at least one per task, message `Rules log: <what>`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.

## Review Focus

1. **A mimic is never named a mimic before it is revealed.** It is "Chest n" in tags and in every line, including the line of the hit that wakes it, and it never appears as a skipped target. The revealing hit's *next* line names "Mimic n". → `a_hidden_mimic_is_a_chest_in_every_line` (Task 7).
2. **Lines about creatures that die or move between record and snapshot.** A goblin killed on the first of the two ticks is gone from the snapshot. Visibility is judged from the positions stored in the record (as events are today), so the kill line still reaches whoever saw the goblin die. → `a_kill_line_reaches_who_saw_it_die` (Task 7).
3. **The log on in a big fight.** Many hits per snapshot must neither blow the bandwidth nor stall the tick. → the per-snapshot byte cap with its "… n more" line, `the_log_is_capped_per_snapshot` (Task 2), and the e2e smoke with the log on (Task 10).
4. **Holding a blocked secondary.** `try_use` runs every tick while RMB is held. A "Too close" line must come at most once per `TOO_CLOSE_EVERY` (1 s) per hero, not 60 times a second. → `too_close_is_logged_once_a_second` (Task 6).
5. **The localStorage accessor throws** (private window, blocked site data). The log still toggles for the session and the page never breaks. → vitest `prefs survive a throwing storage` (Task 8).
