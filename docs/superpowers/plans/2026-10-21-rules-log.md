# Rules log — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A toggleable text log that explains every damage calculation and every effect outcome, with server-assigned creature tags drawn while the log is on. It never lies, never changes the simulation, costs nothing while off, and never reveals what the player cannot see. It is **encapsulated** (the user, 2026-10-22): the feature lives in one folder on each side, so it can be changed or removed easily.

**Architecture:** The feature lives in two folders: `server/src/run/rules_log/` and `client/src/rulesLog/`. The game reaches it only through a fixed list of one-line **hooks** (see "The boundary" below). It hands over plain *facts*: values the game has already computed. The module owns everything else: the tags, the opt-in, the text, the visibility rule, the cap, the wire record and the whole client UI. To stay honest, the game keeps a little more data than today: each hit carries its provenance (`Damage.why`), each ability carries its Attribute breakdown (`Base`), and `apply` reports its outcome. These are ordinary game data, and the module only reads them. Two boundary tests, one per side, pin the hook list, so the hooks cannot spread unnoticed.

**Tech Stack:** Rust (server, `cargo test`), TypeScript + Phaser (client, vitest), ts-rs bindings (`client/src/generated`), msgpack (`server/src/wire.rs`, `client/src/wire.ts`).

**Spec:** [docs/superpowers/specs/2026-10-21-rules-log-design.md](../specs/2026-10-21-rules-log-design.md). Read it whole; "Who sees which lines" is binding.

## Global Constraints

- **Encapsulation** (the user): the log's code lives only in `server/src/run/rules_log/` and `client/src/rulesLog/`. Outside them, the only code that names the log is the hooks in the table below. A task that needs a new hook adds it to the table, to the boundary test, and to TECHNICAL's removal checklist, in the same commit. Game code never formats log text, never checks visibility for the log, and never reads the log's state; the one exception is `rules_log::on(run)`, which hooks use internally.
- **The log never lies:** every logged number is the value the rule used. It is either the same variable handed over as a fact, or a breakdown that the rule's value is itself computed from (`Base::amount()` *is* the ability's damage). No function may recompute a number for the log alone.
- **The log never changes the game:** `level_setup_is_unchanged`, `simulation_is_unchanged_after_waking_the_boss` and `plan_3a_fight_is_pinned` (`server/src/run/mod.rs`) pass unchanged after every task, with the log off **and** (from Task 2 on) with the log forced on. Nothing is re-recorded. Hooks never mutate game state. No new RNG draw, and no change to the order of float operations in any rule.
- **Off costs nothing:** with no player's log on, every hook returns on its first line, no string is formatted, and the encoded snapshot is byte-for-byte today's (the new trailing field is skipped).
- **Names** (the user): "Attributes", never "ability scores"; "ability" means only the LMB primary and RMB secondary; never "elemental", say "damage-type effect". No chance anywhere.
- **No wildcard arms** over `AbilityId`, `Shape`, `EffectKind`, `EffectLook`, `AbilityMod`, `PropKind`, `WeaponKind`, `EquipSlot`, `DamageType`, `EntityKind`, or the new enums (`What`, `Mult`, `EffectOutcome`, `Skip`, `HitOutcome`, `EndReason`, `LineKind`). Each one's text is an exhaustive `match` in `rules_log/text.rs`, so a variant without text does not compile.
- **A very clear font for the log** (the user, 2026-10-22; this overrides the spec's "existing pixel font" for the log): the panel and the tags use **JetBrains Mono** (Google Fonts, weights 400 and 600). It is monospace, so the steps line up in columns; it was made for small sizes; and it tells 0/O and 1/l apart. Panel text is 11 px with line-height 1.35, headlines in 600 and details in 400. Text is light on the dark panel, with contrast of at least 7:1 (the colours below meet it). The module loads the font itself (`panel.ts` adds the `<link>` once, with `display=swap`; until it loads, the fallback is `ui-monospace, Menlo, Consolas, monospace`), so `index.html` stays untouched. The rest of the HUD keeps Press Start 2P.
- **Rounding:** one decimal everywhere, with a trailing `.0` dropped: `n1(9.0) == "9"`, `n1(10.55) == "10.6"`, `n1(-0.04) == "0"`. Percentages are whole: `pct(0.2) == "20 %"`.
- **Text from the server:** records go out as pre-formatted lines (headline + detail lines + a `LineKind` for the colour). The client shows, filters and colours them. (The spec left the wire shape open; text keeps the formatting, its exhaustive matches and its tests in one module, next to the numbers.)
- **Sandbox:** `cd server && cargo test -- --skip export_bindings` (focused: `cargo test --bin '*' <filter> -- --skip export_bindings`). **A task that changes exported data** (protocol, wire, `defs.ts`) regenerates `client/src/generated` with `docker compose -f docker-compose.test.yml run --rm test` from the repo root and commits the changes. If docker is unreachable from the sandbox, the task report says so and the main session runs it.
- **Client checks:** `cd client && bash -lic 'npx vitest run && npx tsc --noEmit && npm run build'`.
- **Commits:** at least one per task, message `Rules log: <what>`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.

## Review Focus

1. **A mimic is never named a mimic before it is revealed.** It is "Chest n" in tags and in every line, including the line of the hit that wakes it, and it never appears as a skipped target. → `a_hidden_mimic_is_a_chest_in_every_line` (Task 7).
2. **Lines about creatures that die or move between record and snapshot.** A goblin killed on the first of the two ticks is gone from `ents`. Visibility is judged from the positions stored in the record (as events are today), so the kill line still reaches whoever saw it die. → `a_kill_line_reaches_who_saw_it_die` (Task 7).
3. **The log on in a big fight.** Many hits per snapshot must neither blow the bandwidth nor stall the tick. → the 4 KB per-snapshot cap with its "… n more" line, `the_log_is_capped_per_snapshot` (Task 2), and the e2e smoke with the log on (Task 10).
4. **Holding a blocked secondary.** `try_use` runs every tick while RMB is held. "Too close" is logged at most once per `TOO_CLOSE_EVERY` (1 s) per hero and slot. → `too_close_is_logged_once_a_second` (Task 6).
5. **The localStorage accessor throws** (private window, blocked site data). The log still toggles for the session and the page never breaks. → vitest `prefs survive a throwing storage` (Task 8).

### Task 3: Hit provenance and the Attribute breakdown (game data)

This task touches no log code: it gives each hit the facts the log will read later.

**Files:**
- Modify: `server/src/defs/damage.rs`, `server/src/defs/weapons.rs`, `server/src/sheet.rs`, `server/src/defs/loadout.rs`, `server/src/defs/attributes.rs`
- Modify (fill `why` at each hit site): `server/src/run/abilities.rs`, `run/ai.rs`, `run/companion.rs`, `run/objects.rs`, `run/bosses/{dragon,demon,lich}.rs`, `run/mod.rs` (lava, `spawn_fire_patch`, hazard pulses), `run/effects.rs` (ticks)

**Interfaces:**
- Produces, in `defs/damage.rs`:
  - `pub fn resolve_parts(d: &Damage, r: &Resistances) -> [f64; DamageType::COUNT]`, each type's `d.amount * share * (1 - res.max(MIN_RESISTANCE))`. `resolve` becomes `resolve_parts(..).iter().sum()`, summed in the same `DamageType::ALL` order, so its results are bit-identical.
  - `#[derive(Clone, Copy, Debug, PartialEq)] pub struct Base { pub given: f64, pub scale: Option<BaseScale>, pub ability_mult: f64, pub mods_mult: f64 }`, with `pub struct BaseScale { pub attr: Attr, pub at: i32, pub have: i32, pub ratio: f64 }`.
    - `pub fn amount(&self) -> f64` is `((given * ratio) * ability_mult * mods_mult).max(0.0)`, in exactly that order, with `ratio` 1 when there is no scale.
    - `Base::plain(v)`.
